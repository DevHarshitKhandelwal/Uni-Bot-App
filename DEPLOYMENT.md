# Deploy UniBot to Render

The main repository includes a Render Blueprint (`render.yaml`) that defines the
static frontend, Node API, and Python RAG service. All three services are built from
`DevHarshitKhandelwal/Uni-Bot-App`; no other GitHub repository is required.

## Deploy

1. Push the latest changes to `DevHarshitKhandelwal/Uni-Bot-App`.
2. In Render, choose **New > Blueprint**, connect `DevHarshitKhandelwal/Uni-Bot-App`,
   and select `render.yaml`. All services in the Blueprint use this same repository.
3. Enter the `GEMINI_API_KEY` for `unibot-rag` and the MongoDB Atlas connection URI for
   `unibot-api` when prompted. Do not commit these secrets or paste them into chat.
   `JWT_SECRET` is generated by Render.
4. Apply the Blueprint and wait for all three services to finish their first build and
   startup. The RAG service embeds its bundled knowledge-base documents at startup.
5. Open the frontend URL. Check `https://<api-host>/api/health`; it should show
   `"ragReady": true` before testing chat.
6. For a phone APK, build again with the deployed API URL:

   ```powershell
   $env:VITE_API_BASE_URL = "https://<api-host>/api"
   npm run build:android
   ```

   Run the command from the `client` directory, then publish the generated APK on the
   website. The APK currently in the repository is configured for local-network testing.

## Free-tier limitations

Render free web services can sleep when idle, so the first request may take a while.
Their local files are ephemeral: the RAG index is rebuilt after restarts, and uploaded
files stored only on the API filesystem are not durable. The RAG service needs the
Gemini API key and its bundled course documents to initialize. A working MongoDB Atlas
URI is required for persistent application data.
