# Deploy UniBot to Render

The main repository includes a Render Blueprint (`render.yaml`) that defines the
static frontend, Node API, and Python RAG service. All three services are built from
`DevHarshitKhandelwal/Uni-Bot-App`; no other GitHub repository is required.

## Deploy

1. Push the latest changes to `DevHarshitKhandelwal/Uni-Bot-App`.
2. In Render, choose **New > Blueprint**, connect `DevHarshitKhandelwal/Uni-Bot-App`,
   and select `render.yaml`. All services in the Blueprint use this same repository.
3. Configure Render secrets when prompted:
   - `GEMINI_API_KEY` for `unibot-rag`.
   - `OPENAI_API_KEY` for `unibot-rag` if you want OpenAI as an optional fallback.
   - `MONGODB_URI` for `unibot-api`.
   - `ADMIN_USERNAME` and a unique `ADMIN_PASSWORD` of at least 16 characters for
     administrator access.
   Do not commit secrets or paste them into chat. `JWT_SECRET` is generated by Render.
   Render generates the internal `RAG_SERVICE_TOKEN` automatically and shares it
   between the API and RAG services.
4. Apply the Blueprint and wait for all three services to finish their first build and
   startup. If Gemini embedding quota is exhausted, RAG starts with BM25 retrieval and
   retries vector indexing in the background.
5. Open the frontend URL. Check `https://<api-host>/api/health`; it should show
   `"ragReady": true` before testing chat.
6. Open the website’s **Admin** section and sign in with `ADMIN_USERNAME` and
   `ADMIN_PASSWORD`. The dashboard shows observed quota status and lets you switch
   between configured providers. Gemini does not expose an exact credit balance to
   UniBot. To enable OpenAI fallback, set `OPENAI_API_KEY` in the `unibot-rag` Render
   environment first, then redeploy that service.
7. For a phone APK, build again with the deployed API URL:

   ```powershell
   $env:VITE_API_BASE_URL = "https://<api-host>/api"
   npm run build:android
   ```

   Run the command from the `client` directory, then publish the generated APK on the
   website. The APK currently in the repository is configured for local-network testing.

## Free-tier limitations

Render free web services can sleep when idle, so the first request may take a while.
Their local files are ephemeral: the RAG index is rebuilt after restarts, and uploaded
files stored only on the API filesystem are not durable. The admin page can switch
between Gemini and OpenAI only when their keys are configured in Render; it cannot read
an exact remaining-credit balance from either provider. A working MongoDB Atlas URI is
required for persistent application data and the selected AI provider setting.

For local Docker Compose, configure one `RAG_SERVICE_TOKEN` in `server/.env`; Compose
passes that same secret to both the API and RAG containers.
